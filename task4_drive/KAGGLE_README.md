## v5 为什么退步（我的两个失误）

**失误一：主模型训练量反而减少了**

v3 用的是固定 `epochs=250/90`，v5 改成步数预算 `900/600`：

| | 512 阶段 | 768 阶段 |
| --- | --- | --- |
| v3（15 张时） | 250ep × 4 步 = **1000 步** | 90ep × 8 步 = **720 步** |
| v5 | 225ep × 4 步 = 900 步 | 75ep × 8 步 = 600 步 |

少了 10~17%。我本想省时间，结果削掉了主力模型的训练。

**失误二：把较弱的架构等权混入**

`mit_b2`（SegFormer）如果比 `effb4` 弱，等权平均会被它拖下来。
v5 没有做任何加权，直接 8 个模型等权。

**附带发现：外部数据一次都没生效过**

如果 v3 真用了 38 张外部数据，250 epoch 会是 3500 步、需要 15 小时以上，根本跑不完。
所以前几次运行都**没有上传 `ext-data`**，外部数据这条线从未真正贡献。
我之前一直按"有外部数据"做时间预算，是判断错误。

## v6 的修正

1. **主模型步数提到 1200/850**（高于 v3 的 1000/720）
2. **第二架构默认关闭** —— v5 证明等权混入会拉低总分
3. **加入按 OOF 加权的集成** —— 以后若启用第二架构，权重由 OOF Dice 自动决定：
   低于最佳架构 0.005 以上的给 0.3 权重，而不是等权
4. **保留 8 向 TTA**（4 翻转 + 180°，实测 +0.0015）
5. **修正顺序**：先算 OOF 权重，再预测测试集（之前是先预测后校验）

## 关键实现细节（都验证过）

1. **概率图保持原生分辨率，先阈值再按官方方式缩放到 512** ——
   若先缩放再阈值，BILINEAR 会稀释细血管峰值，实测 Dice 从 0.847 掉到 0.778（−0.069）。
2. **每个架构/seed 开始前重新 `seed_everything()`** —— 否则权重初始化完全相同，
   集成退化成"同一模型训两遍"。
3. **checkpoint 存 `arch` / `encoder`** —— 推理时据此重建网络。
4. **RLE 用官方 `turn_to_str` 逻辑** —— 与 `segmentation_to_csv.py` 逐字节比对 20/20 一致。
5. **血管 = 255**（非零即前景），与训练标签一致。任务说明写的"血管=0"与数据和官方脚本矛盾。

## 已穷尽、确认无效的手段

| 手段 | 结果 |
| --- | --- |
| 阈值扫描 0.30–0.76 | 最优 0.8473 @0.46，+0.0003（噪声） |
| 滞后阈值（双阈值+连通性）12 组 | 全部变差，最差 −0.032 |
| 形态学闭运算 3×3 / 5×5 | 0.8467 / 0.8423，变差 |
| 小连通域剔除 | ±0.000 |
| TTA 4→8→16 向 | 0.8213 → 0.8228 → 0.8223 |
| 公开预训练权重（正确阈值重测） | MHasan 0.7823、Ogrodowski 0.0082，均低于 0.85143 |
| 等权混入 Transformer 架构 | 0.85143 → 0.85096 |

滞后阈值全部变差这点最关键：**低阈值带进的噪声比补回的细血管更多**。
细血管召回 0.60（粗血管 0.92）是硬瓶颈 —— 不是决策阈值的问题，是模型没学到。

## 对成绩的诚实判断

**0.85143 大概率就是这条路的实际水平**，后续每次改动都在 ±0.001 噪声范围内。
每个候选方案要 4~6 小时 Kaggle 配额才能验证，投入产出已经很低。

真正的突破需要换更强的检测思路（专门的细血管多尺度模块、或大量外部数据预训练），
而不是继续在当前架构上调参。
